# Correctness review, 2026-10-22

Reviewed the JavaScript matcher, its renderer/worker integration, immutable SelectList preparation, and the file finder's metadata lifecycle. The baseline library is `0ac7a0f8021ff20e751cba2b06af24583d9af76c`. The review adds no backend, dependency or result limit.

## Repaired defects

- Command-T reused zero scores to reject refinements even when its long-input approximation selected a different alignment. An uppercase query could reject a long candidate, while appending a letter should recover a matching earlier uppercase segment. Cached and fresh searches disagreed. Approximate candidates are now rescored instead of inheriting that rejection.
- The long-input path ignored `maxGap` and smart-case penalties. It now enforces both. If the latest unrestricted alignment violates the gap bound, reachable query prefixes locate a valid earlier alignment; failure to find one rejects the candidate. Large-input scores remain approximate and bounded-gap validation can require additional work.
- Highlight extraction expanded the complete alignment as function arguments. A 150000-character exact query threw `RangeError` instead of returning indexes. Appending indexes iteratively removes the argument-stack limit.
- File-index snapshots were identified by a revision number local to each helper process. A replacement helper could have the same revision and reference directory as the previous one and reuse its obsolete snapshot. Snapshots now carry a per-instance ownership token; the finder checks its current generation again after asynchronous record preparation.
- SelectList preparation checked cancellation between batches but not after the last identity callback. A cancellation from that callback incorrectly resolved and cached the preparation. A final signal check prevents that publication.
- Finder refreshes could outlive package/window teardown, and repeated helper `close()` calls did not await the original process termination. Refreshes are explicitly cancelled on teardown, inactive finders cannot recreate metadata workers, and every close caller receives the same termination promise.
- A closed metadata helper could still satisfy queued reads from its cached snapshot, hiding its failure. Refreshing the finder also retained that failed helper. Closed helpers now reject queued operations, including cache hits and empty updates; an explicit finder refresh replaces the failed helper and rebuilds metadata from the shared index.

## Verification

Regression tests reproduce the long-input failures and check both fresh and cached/async matching. An independent exhaustive subsequence oracle checks bounded-gap eligibility and returned alignments on 256 seeded long candidates, including slash/underscore aliases. Another seeded test exercises 240 state transitions across both algorithms and diacritic modes, mixing query edits, highlights, one-candidate matching, candidate replacements, limits, scoring modifiers and concurrent asynchronous requests. Results are compared with fresh matchers, including complete scores, ordering and highlights where requested.

Finder integration tests cover replacement of the metadata helper while a snapshot is being prepared, colliding revisions across helper instances, package deactivation during a refresh, repeated close calls, queued cached reads after closure, and recovery from helper failure. Core tests cover cancellation from the final identity callback and the corrected long-input matching through an actual Chromium worker. Local runs passed 151 library specs and 515 combined integration specs; the final finder-only suite passed 160 specs after adding failure-recovery coverage. These checks supplement the existing Unicode, incremental eligibility, mutation, worker cancellation and package integration suites; they are not a proof that every possible input is defect-free.

## Performance check

Four fresh Node processes ran before/after/after/before on the same 100000-path slice of the existing private project corpus. Each algorithm had two warmups and five measured sequences per process: `s`, `se`, `sel`, `main`, `s`. Full ordered-result hashes match the baseline at every stage. The long-input option fixes intentionally change the incorrect edge-case results described above; those edge cases are tested separately.

Medians in milliseconds, with the initial and repeated `s` kept separate:

The largest increase is about 6% in initial Command-T matching; refinement and cached-query measurements remain close to baseline. This limited sample is a regression check, not evidence of a general speedup or a zero-cost fix, and it covers the library rather than UI rendering.
