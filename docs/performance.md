# Performance and adoption

This library is a JavaScript port of fuzzy-native. The initial port had a significant regression on uncached Fuzzaldrin query extensions. A follow-up preserves the same ranking while caching subsequence eligibility and path metadata and specializing short ASCII alignment. On the paired renderer runs, extending `se` to `sel` over 100000 paths improved from 155.90 ms to 93.70 ms, compared with native's 90.60 ms. At 10000 paths the corresponding figures were 22.05, 14.75 and 14.95 ms. These are local Windows measurements, not a universal cross-platform speed guarantee.

The [initial editor evaluation](https://github.com/lumine-code/lumine/blob/master/docs/fuzzy-matching-evaluation-2026-10-20.md) records the original decision and consumer review. The [refinement follow-up](https://github.com/lumine-code/lumine/blob/master/docs/fuzzy-refinement-2026-10-20.md) records the proof of safe eligibility reuse, VS Code research, optimization experiments and worker measurements. Both native algorithms remain available; their scores and highlights remain covered by differential tests.

`benchmark/worker-pool.js` and `benchmark/browser-pool.js` are diagnostic transports, not production Matcher APIs. They require a fixed candidate set and Fuzzaldrin's default ordering; arbitrary score modifiers and update/cancellation policy are not implemented there. Browser workers use only the library's JavaScript and data tables, without Node integration or changes to Electron security settings.

Run the existing specs with `npm test`. `benchmark/differential.js <native.node> <corpus.json>` compares both algorithms over a seeded mixed ASCII/Unicode corpus, including case modes, optional separators, expansion offsets and ordered score groups. The native binary is supplied explicitly and is never a runtime dependency.

For timing, run `node benchmark/run.js --module <implementation> --corpus <corpus.json> --output <report.json>` in fresh alternating processes. For memory, run `node --expose-gc benchmark/memory.js <implementation> <corpus.json> 100000`. A corpus is a JSON array of paths; larger requested sizes repeat it under numbered project roots. Use CPU profiling separately from timing runs. Reports include runtime metadata and retain raw samples rather than only an aggregate speed ratio.
